# AeroIcing Watch 3D 항로 재생 작업명세서

작성일 2026-11-12 · 상태 초안 · 구현 기준 `32c93f5`

## 1. 목표와 범위

사용자가 3D 지도에서 인천–하네다의 두 후보 항로를 눈으로 비교해 하나를 직접 선택한다. 선택한 항로를 재생하면 항공기 모델이 순항 경로를 따라 이동한다. 사용자는 일시정지하거나 관심 구간으로 이동해 그 지점의 통과 예정 시각, 예보 바람, 지상속도, 기온·습도와 추정 연료를 확인한다.

| 단계 | 납품 범위 | 시작 조건 |
|---|---|---|
| 1. 3D 항로 재생 | 기존 두 후보를 지도에서 선택, 항공기 이동, 카메라 추적, 타임라인, 구간 정보, 기존 비교 화면 연동 | 현재 보관 IFS 시나리오로 시작 |
| 2. 위성 관측 연동 | 관측 프레임을 지도에 표시하고 선택 항로를 따라 구름 높이 단면을 시각화 | 시공간이 겹치는 사례 확보, 높이 기준과 재배포 권한 확인 |
| 3. 지도에서 후보 작성 | 지도 클릭으로 경유점 추가·이동·삭제, 초안 항로와 재계산 결과 표시 | IFS 평가 API 연결, 서버 호스팅과 실패 처리 검증 |

## 2. 1단계 사용자 흐름

1. 기존 공개 비교 화면에서 **3D Replay**를 연다. 첫 화면은 RKSI, RJTT, 중간 경유점과 두 후보를 한눈에 보여준다.
2. 지도 선 또는 키보드로 접근 가능한 후보 카드에서 항로를 고른다. 지도 강조, 카드 선택 상태, 타임라인과 구간 정보가 같은 후보를 가리킨다. 선이 겹치면 카드로 후보를 확실히 고를 수 있다.
3. 재생을 누르면 항공기가 선택한 선을 따라 움직인다. 일시정지, 처음으로, 구간 탐색, 재생 속도 변경을 지원한다. 전체 보기와 항공기 추적 보기를 제공한다.
4. 항로 위의 구간 또는 타임라인의 위치를 선택하면 모델과 지도 강조가 그곳으로 이동하고, 기존 기상 상세를 갱신한다. 후보를 바꾸면 재생을 멈추고 새 후보의 시작 위치를 표시한다.

화면에는 보관 예보, UTC, 순항 재생, 가속 배율을 표시한다. `FL300`은 계산에 사용한 압력고도로 표시하고, 렌더링 높이는 표시용 근사값으로 명시한다. 기존 RKSI–RJTT 사례에는 동시간대 CTPS가 없어 관측 상태를 **자료 없음**으로 표시한다.

## 3. 데이터와 구현 작업

| ID | 작업 | 산출물과 완료 기준 |
|---|---|---|
| R1 | 재생 데이터 계약 정의 | 기존 내보내기에 버전이 지정된 재생 데이터를 추가한다. 후보 ID, WGS84 위경도, 위치별 UTC, 표시 높이(m)와 높이 기준, 구간 ID, 항로 시작·끝 시각을 포함한다. 기존 예보 출처와 IFS 순항 가정도 조회할 수 있게 한다. |
| R2 | 시간·좌표 궤적 생성 | IFS 구간 생성 로직의 경계 좌표와 소요 시간을 내보낸다. 기존 파일의 구간 ETA는 **중점 시각**으로 사용한다. 구간 경계 시각은 출발 시각과 구간 소요 시간을 바탕으로 생성하고, 경유점은 대응하는 구간 경계에 포함한다. |
| R3 | 3D 장면과 항공기 표시 | CesiumJS로 지구본, 두 항로 선, 경유점, 항공기 아이콘 또는 경량 모델을 표시한다. 항공기 방향은 이동 방향을 따른다. 좌표 보간 중 모델이 선에서 벗어나거나 경유점을 가로질러 가지 않는지 확인한다. |
| R4 | 선택과 재생 상태 연결 | 후보 ID·구간 ID·재생 시각을 기준으로 3D 장면과 카드, 타임라인, 기상 패널을 동기화한다. 재생 종료 시 정지하고, 데이터가 끊기는 경우 마지막 계산 가능 위치와 중단 이유를 표시한다. |
| R5 | 정적 배포와 대체 화면 | 3D 페이지와 필수 자산을 `static/route-demo/` 배포 범위에 포함한다. Cesium 배경과 항공기 모델의 사용 조건을 확인하고, 공개 데모는 개인 API 키 없이 로딩되게 한다. WebGL 사용이 어려우면 기존 2D 비교 화면으로 이동할 수 있게 한다. |

항로 계산은 기존 IFS 평가기를 재사용한다. 첫 단계는 배포된 보관 응답을 재생하며, 기존 거리·시간·연료 값과 비교 화면의 구간 의미를 유지한다. [IFS 항로 평가](IFS_Route_Evaluation.md) · [기존 내보내기 코드](../tools/export_route_demo.py)

## 4. 위성 관측 연동과 지도 편집

### S1. CTPS 자료 선정과 정규화

- 두 후보에 대해 IFS 유효 시각과 CTPS 관측 시각이 겹치는 보관 사례를 선정한다. 소스, 관측 시각, 확인 가능한 가용 시각, 공간 범위, 품질 상태와 공개 이용 조건을 기록한다.
- 관측 격자를 위경도로 배치하고 구름 상단, 추정 하단, 위상, 품질·결측 마스크를 추출한다. 관측 시각과 항공기 중점 ETA의 차이를 화면에 표시한다. 시간 정합 조건과 자료 허용 범위는 사례 선정 시 문서화한다.
- CTPS와 항공기 높이의 기준을 확인한다. 기준을 정합할 수 있는 자료에 한해 같은 수직 좌표에 그린다. 3D 화면의 과장 배율을 적용하면 배율도 표기한다.

### S2. 위성 레이어와 항로 단면

- 관측 분포를 지도 표면에 표시하고, 선택 항로를 따라 구름 상단과 추정 하단을 수직 단면으로 표시한다.
- 하단 누락은 상단 표식으로, 범위 밖과 품질 제외 구간은 공백 및 상태로 표현한다. 관측 프레임 시각은 항공기 재생 시각과 별도로 표시한다.
- CTPS 단서와 IFS 온도·습도 스크리닝은 각각 출처와 상태를 보여준다. 결빙 정확도는 미평가로 표기한다.

### E1. 경유점 편집과 재계산

- 사용자가 지도에서 중간 경유점을 찍고 이동·삭제한다. 입력 중 경로를 초안 상태로 보여준다.
- 편집된 후보를 기존 `POST /api/route-review/evaluate`에 동일한 예보·출발 시각·항공기 조건으로 보내고, 성공한 결과로 시간표와 비교값을 갱신한다.
- 중복 경유점, 예보 범위 밖, 번들 없음, 평가 실패를 화면에 표시한다. 편집하거나 재요청하는 동안 이전 결과를 현재 초안의 결과로 표시하지 않는다.

## 5. 검수 기준

| 항목 | 통과 조건 |
|---|---|
| 선택 | 두 후보를 지도와 키보드로 각각 선택할 수 있다. 선택 변경이 선, 카드, 모델 위치와 구간 정보에 반영된다. |
| 재생 | UTC가 순서대로 진행된다. 시작점, 경유점, 마지막 지점을 통과한다. 재생·일시정지·탐색·카메라 전환이 작동한다. |
| 수치 | 후보별 시간과 연료 합계가 기존 보관 결과와 표시 정밀도 내에서 일치한다. 같은 구간에서 2D·3D가 같은 중점 ETA와 기상값을 보여준다. |
| 결측 | IFS 구간 결측과 CTPS 자료 없음이 각각 표시된다. 위성 연동 후에는 하단 누락과 품질 제외를 별도로 확인한다. |
| 배포 | HTTPS 공개 URL에서 로그인 없이 재생된다. 데스크톱과 모바일에서 후보 선택·재생을 확인하고, WebGL 사용 불가 시 2D 화면에 접근할 수 있다. |

1단계 작업 순서는 **R1 → R2 → R3·R4 → R5 → 공개 URL 검수**다. 위성 사례 탐색은 R1·R2와 병행할 수 있다. 2단계와 3단계는 각 시작 조건을 충족한 뒤 별도로 검수한다.
