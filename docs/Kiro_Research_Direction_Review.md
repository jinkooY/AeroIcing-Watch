작성일 2026-11-12 (KST). 검토 대상은 `main` 커밋 `71514ac`의 Kiro 스펙과, 메인 체크아웃에 커밋되지 않은 구현·계획 문서(`backend-first-plan.md`, `docs/IFS_Route_Evaluation.md`, `docs/WeatherPath_Port_Inventory.md`, `src/`, `tools/`, `tests/`)다. 코드는 수정하지 않았다.

## 1. 결론

1. **주제는 적합하다.** 위성 관측, 수치예보, 운항관리라는 서로 다른 영역을 한 화면에 엮는 구성이라 Frankenstein 부문에 맞고, 공공 위성 자료를 쓰는 점이 Innovation 항목에 유리하다.
2. **지금의 확장 방향은 점수와 어긋난다.** 심사 5개 항목이 각 20%인데, 최근 작업(IFS 경로 평가, OpenAP 연료, 항공편 조회, 비용 가설)은 그중 어느 항목도 직접 올리지 못한다. Kiro 활용, 디자인, 발표 세 항목(합계 60%)은 현재 거의 비어 있다.
3. **착빙 판정의 과학적 약점이 하나 있다.** 순항고도(FL300~350)는 영하 40도 이하라 과냉각 수적이 거의 없다. 실제로 RKSI–RJTT FL300 검증에서 49개 구간 중 착빙 조건 충족이 0건이었다. 지금 설계대로면 데모에서 보여줄 착빙이 없다.
4. **권장 범위는 "관측 단면 + 비행 프로파일 기반 착빙층 + 2프레임 리플레이"까지다.** 연료 순위, 후보 경로 비교, 항공편 조회, 비용 측정은 동결한다.
5. **가장 큰 실격 위험은 Kiro 사용 증거다.** `.kiro`에 스펙과 스티어링 1개만 있고 훅, PBT, MCP가 없다. 구현 대부분이 Kiro 밖에서 이뤄졌다면 남은 작업은 Kiro 안에서 진행해야 한다.

## 3. 연구방향 검토

### 3.1 유지할 것

- **결정론적 판정, LLM 배제.** 안전 관련 판단에서 근거 추적이 가능하다는 점이 심사에서 설득력 있다.
- **증거 상태 구분.** 맑음, 영역 밖, 품질 불량, 밑면 미상을 따로 표시하는 설계는 이미 구현에 반영돼 있고(`retrievalState`), 이 제품의 차별점이다.
- **CTPS 과냉각 신호를 "구름 꼭대기 증거"로만 취급**한다는 `backend-first-plan.md`의 원칙.

### 3.2 고쳐야 할 것

**(가) 순항고도 단일 값 판정을 비행 프로파일 판정으로 바꾼다.**
착빙은 대체로 0 ~ -20도 구간의 과냉각 수적에서 생긴다. 제트기 순항고도에서는 해당이 없고, 상승·강하 구간과 저고도 운항(터보프롭, 단거리 국내선)에서 문제가 된다. 현재 규칙 `HIGH: supercooled AND 고도 ∈ [base, top]`은 고정 순항고도를 가정해 대부분 NONE이 나온다. 상승–순항–강하를 단순 사다리꼴로 넣고 각 표본의 계획 고도로 판정해야 한다.

**(나) 위성과 예보를 따로 두지 말고 하나의 착빙층으로 결합한다.**
지금은 CTPS 신호와 IFS 온도·습도 신호가 별도 출력이다. NASA Langley의 위성 착빙 알고리즘(Smith et al. 2012, JAMC)은 위성의 구름 꼭대기 온도, 상(phase), 수분 경로로 착빙 여부를 정하고 착빙층의 상하 경계를 따로 추정한다. 같은 구조를 단순화해 적용한다.

```
착빙 후보층 = [max(추정 구름 밑면, 0도 고도), min(구름 꼭대기, -20도 고도)]
  조건: CTPS 과냉각 플래그 = 1 (또는 liquid 이고 CTT < 0도)
  0도·-20도 고도: IFS 온도 프로파일 (없으면 CTT와 표준 감률로 추정하고 "추정" 표기)
노출 = 계획 고도가 착빙 후보층 안에 있음
```

이미 수집한 IFS 기온 자료를 그대로 쓸 수 있으므로 추가 데이터가 필요 없다. IFS 기압면이 850/500/300/250 hPa 네 개뿐이라 0도 고도 보간이 거칠다. 700 hPa와 925 hPa 추가를 권한다.

**(다) 등급 이름을 위험도에서 증거 수준으로 바꾼다.**
HIGH/MODERATE/LOW는 강도 예보처럼 읽히지만 실제로는 강도를 산출하지 않는다. 다음처럼 바꾸면 과장이 없고 면책 문구와도 맞는다.

| 표시 | 조건 |
| --- | --- |
| Observed supercooled layer at planned altitude | 위성 과냉각 신호 + 계획 고도가 착빙 후보층 안 |
| Possible (forecast only) | 위성 신호 없음 또는 상층운에 가림, IFS 온도·습도 조건 충족 |
| Not indicated | 구름 없음 확인 또는 고도가 층 밖 |
| Not assessed | 영역 밖, 품질 불량, 자료 없음 |

**(라) 신규성 주장을 정확히 한다.**
국가기상위성센터는 이미 GK-2A 착빙(ICING) L2 산출물을 만들며, ATBD에 따르면 착빙 유무 마스크, 강도, 온습도 프로파일 기반 발생 고도를 산출한다. 따라서 "위성으로 착빙을 탐지한다"는 새롭지 않다. 이 프로젝트의 기여는 **경로를 따라 세운 수직 단면, 근거 추적, 시간 경과에 따른 변화 표시**다. 공식 ICING 산출물은 경쟁 대상이 아니라 일치도 비교 대상으로 쓴다.

**(마) 검증 주장의 수위.**
독립적인 착빙 조종사 보고가 없으므로 정확도는 말할 수 없다. 2~3개 사례에서 GK-2A ICING 산출물 및 당시 SIGWX/AIRMET과의 일치 여부만 제시하고 "agreement"로 표기한다. `tools/validate_ifs_icing.py`의 diagnostic 모드가 이 용도에 맞다.

**(바) 데모 사례를 겨울 사례로 교체한다.**
현재 데모 프레임은 2026-09-01(과냉각 신호 4개)이다. 한기 유입 때 서해와 제주 부근에 생기는 층적운은 과냉각 수적이 많아 사례로 적합하다. 11월 중·하순 한기 남하 시점의 CTPS·DCOEW 연속 프레임과 같은 시각 IFS를 지금부터 수집한다. 경로는 KO 영역(32–44.5°N, 122–134.5°E) 안에 완전히 들어오는 RKSS/RKSI–RKPC를 주 사례로, RKSI–RJFF를 보조 사례로 쓴다. RKSI–RJTT는 영역 밖 처리 시연용으로만 둔다.

### 3.3 한계로 명시할 것

- 수동 영상기는 최상층 구름만 본다. 상층운 아래의 과냉각층은 보이지 않는다.
- 구름 밑면은 통계 추정(Noh et al. 2017)이며 야간에는 불확실성이 더 크다. 단면에 불확실 표기를 넣는다.
- 착빙 강도, 확률, 기종별 영향은 산출하지 않는다.

### 4.2 동결 (코드는 두되 더 투자하지 않고 데모에서 제외)

- OpenAP 연료 계산과 후보 경로 순위

동결 이유는 세 가지다. 심사 항목에 기여가 작고, 연료 수치는 검증 근거가 없어 질문을 받으면 방어하기 어렵고, 3분 영상에 담을 이야기가 흐려진다. 제출문의 "What's next"에 한 줄로 남긴다.

## 5. 작업지시서

각 지시서는 Kiro에서 스펙 → 설계 → 작업 순으로 진행한다. 코드 작성 지시가 아니라 Kiro에 넘길 요구사항이다.

### WO-1 범위 동결과 저장소 정리 (11/12–11/13)

- 메인 체크아웃의 미커밋 작업을 논리 단위로 나눠 커밋한다. 커밋 이력이 제출 기간 내 작업의 증거다.
- `backend-first-plan.md`의 2·3단계(연료 순위, 비용 측정)를 "post-submission"으로 옮기고 4.1의 범위를 반영한다.
- README에 "Pre-existing work" 절을 만들어 WeatherPath에서 이식한 파일과 함수, 새로 작성한 부분을 표로 적는다.
- OpenAP의 라이선스를 확인한다. Apache-2.0과 맞지 않으면 선택 의존성으로 분리하거나 제거한다.
- `data/airports.json`에서 KO 영역 밖 공항(ZBAA, ZSPD, ZGGG, VHHH, RCTP, RJTT, RJAA, RJCC 등)은 "partial coverage"로 표기하거나 뺀다.
- 완료 기준: `git status`가 깨끗하고, README만 읽어도 재사용 범위를 알 수 있다.

### WO-2 Kiro 작업 체계 구축 (11/13–11/15)

- 스펙을 세 개로 나눈다: `observation-cross-section`(기존, 완료 표시), `icing-layer-fusion`(WO-3), `replay-and-ui`(WO-4, WO-5). 요구사항은 수용 기준을 검증 가능한 문장으로 쓴다.
- 스티어링을 `product.md`, `tech.md`, `structure.md`, `science-guardrails.md`로 나눈다. 마지막 파일에는 3.2의 표기 규칙(강도·확률 주장 금지, 미평가를 맑음으로 표시 금지, 단위와 UTC 규약)을 넣고 `src/analysis/**`에만 적용되게 한다.
- 훅을 최소 3개 만든다: 분석 코드 저장 시 관련 테스트 실행, 프로파일 스키마 변경 시 뷰어 검증기 대조, 스펙 변경 시 README API 절 동기화.
- 속성 기반 테스트 대상을 스펙에 명시한다:
  - 경로 표본의 거리는 0에서 시작해 단조 증가한다.
  - 모든 응답은 뷰어 `validProfile()` 규칙을 통과한다.
  - 착빙 후보층은 항상 [밑면, 꼭대기] 안에 있고 하한 ≤ 상한이다.
  - 미평가 표본은 어떤 입력에서도 "Not indicated"가 되지 않는다.
  - 리플레이는 결정 시각 이후 자료를 쓰지 않는다.
- MCP는 실제로 쓸모가 있을 때만 붙인다. 후보는 보관 프레임 목록과 메타데이터를 Kiro가 조회하는 소형 서버다.
- 각 기능을 쓴 날짜, 프롬프트 요지, 결과, 스펙 방식과 즉석 지시 방식의 차이를 `docs/kiro-usage-log.md`에 기록한다. 활용 설명문은 이 기록에서만 쓴다. 사용하지 않은 기능은 적지 않는다.
- 완료 기준: `.kiro` 아래에 specs 3, steering 4, hooks 3 이상이 있고 PBT가 실제로 결함을 하나 이상 잡은 기록이 있다.

### WO-3 착빙층 결합 엔진 (11/14–11/19)

- 입력: CTPS 표본(꼭대기, 추정 밑면, 상, 과냉각 플래그, CTT), IFS 기온·습도 프로파일, 비행 프로파일.
- 비행 프로파일: 출발·도착 표고, 순항고도, 상승률·강하율 기본값으로 만든 사다리꼴. 표본마다 계획 고도와 ETA를 갖는다.
- 0도와 -20도 고도를 IFS에서 구한다. IFS가 없으면 CTT와 표준 감률로 추정하고 방법을 필드에 남긴다.
- 3.2 (나)의 규칙으로 착빙 후보층을, (다)의 표로 표본별 증거 수준을 정한다. 경로 요약은 수준별 거리(km)와 구간 목록으로 낸다. 단일 "최고 등급" 배지는 쓰지 않는다.
- IFS 수집 기압면에 925, 700 hPa를 추가한다.
- 기존 `icingRisk: null`, `assessmentState: not_assessed` 필드와 `/api/icing/cross-section` 계약은 유지하고 필드를 덧붙인다.
- 완료 기준: 겨울 사례에서 강하 구간에 "Observed" 표본이 나오고, 같은 경로를 순항고도만으로 평가하면 나오지 않는다. 판정 규칙과 버전이 응답에 들어 있다.

### WO-4 사례 수집과 리플레이 (11/13 시작, 상시)

- 11월 중·하순 한기 남하 사례 2건 이상에서 CTPS, DCOEW(주간), GK-2A ICING 산출물의 연속 프레임 6개 이상과 같은 시각 IFS를 보관한다. 원본 수신 시각을 기록한다.
- 사례마다 당시 SIGWX 또는 AIRMET을 캡처해 출처와 함께 보관한다.
- 리플레이는 프레임 t와 t+1의 표본별 증거 수준 차이를 계산해 변화 구간(시작·끝 거리, 이전·이후 수준, 근거 프레임)을 낸다. 항공기 위치 진행과 재순위 계산은 넣지 않는다.
- ICING 산출물과의 일치도를 사례별 표로 만든다. 표본 수와 조건을 함께 적는다.
- 완료 기준: 변화가 있는 사례 1건, 자료 누락 프레임이 낀 사례 1건을 재현할 수 있다.

### WO-5 화면 설계와 구현 (11/18–11/26)

- 사용자는 한 명으로 좁힌다: 국내선·근거리 노선의 운항관리사가 출발 전 브리핑에서 상승·강하 구간 착빙을 확인하는 장면.
- 구성: 왼쪽에 경로·고도·사례 선택, 가운데에 단면(구름층, 착빙 후보층 음영, 0도·-20도 선, 비행 프로파일 선), 위에 작은 지도(경로와 위성 영역 경계), 오른쪽에 선택 표본의 근거 패널(자료원, 관측 시각, 품질, 밑면 추정 방법), 아래에 프레임 조절.
- 관측, 예보, 추정, 모의 자료를 무늬와 글자로 구분한다. 색만으로 구분하지 않는다. 키보드 조작을 유지한다.
- 빈 상태, 영역 밖, 자료 없음 화면을 따로 설계한다.
- 문구는 "착빙 없음"이 아니라 "표시되지 않음"으로, 고도 제안은 뺀다(규정상 조언처럼 읽힐 수 있고 밑면 추정 불확실성이 크다).
- 완료 기준: 4.3의 30초 시나리오를 처음 보는 사람이 설명 없이 따라갈 수 있다.

### WO-6 배포 (11/24–11/27)

- 보관 사례를 저장소에 포함하거나 빌드 시 프로파일로 변환해, API 키와 외부 호출 없이 동작하게 한다. KMA 원본 재배포 조건을 확인하고 가공 결과만 싣는 쪽을 우선한다.
- 정적 호스팅(사례 JSON 내장)을 기본으로 하고, 임의 경로 재표본이 필요하면 소형 서버 하나를 둔다. 심사 기간이 2027년 1월 29일까지이므로 그때까지 유지한다.
- 화면 하단에 출처 표기: KMA/NMSC GK-2A, ECMWF Open Data, Noh et al. (2017), 면책 문구.
- 완료 기준: 시크릿 창에서 URL만으로 4.3 시나리오가 재현된다.

### WO-7 제출물 (11/27–12/3)

- 영상(3분 이내): 문제 20초, 겨울 사례 단면과 강하 구간 노출 70초, 프레임 변화 30초, Kiro 활용(스펙, 훅, PBT가 잡은 결함) 40초, 한계와 다음 단계 20초.
- 설명문: 부문 Frankenstein, 결합한 요소(정지궤도 위성 L2, 전지구 예보, 비행 프로파일, 브라우저 Canvas), 기존 코드 공개, 검증 수위.
- Kiro 활용문: `kiro-usage-log.md`에서 발췌.
- 블로그 글 1편과 소셜 게시 1건(선택).
- 12월 1일: 크레딧 신청 마감 확인. 12월 3일 KST: 제출. 12월 4일은 예비일.
